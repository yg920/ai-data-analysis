# TIL - Frontend Chapter 01

## 오늘 배운 내용

오늘은 HTML 파일을 Live Server로 실행하고, 브라우저와 Web Server가 어떻게 연결되는지 확인했다.

또한 Chrome DevTools를 이용해 HTML 구조와 Network 요청을 확인하는 방법을 학습했다.

---

# 1. HTML 기본 구조

기본적인 HTML 문서를 작성했다.

```html
<!DOCTYPE html>

<html lang="ko">

<head>

    <meta charset="UTF-8">

    <meta name="viewport" content="width=device-width, initial-scale=1.0">

    <title>Frontend 첫 실습</title>

</head>

<body>

    <h1>Frontend 학습을 시작합니다.</h1>

    <p>첫 번째 웹페이지입니다.</p>

</body>

</html>
```

HTML 문서는 크게 다음 구조로 구성된다.

```text
html
 ├─ head
 │   ├─ meta
 │   └─ title
 │
 └─ body
     ├─ h1
     └─ p
```

`head`에는 문서 정보가 들어가고, `body`에는 실제 브라우저 화면에 표시되는 내용이 들어간다.

---

# 2. Live Server 실행

처음에는 다음 주소로 접속했지만 페이지가 열리지 않았다.

```text
http://127.0.0.1:5500/
```

브라우저에서는 다음 오류가 발생했다.

```text
ERR_CONNECTION_REFUSED
```

원인은 HTML 코드가 아니라 **Live Server가 실행되지 않은 상태에서 5500번 포트에 접속했기 때문**이었다.

VS Code에서 `index.html`을 우클릭한 후 다음 기능을 실행했다.

```text
Open with Live Server
```

이후 정상적으로 웹페이지가 브라우저에서 실행되었다.

---

# 3. localhost와 127.0.0.1

Live Server를 실행하면 다음과 같은 주소를 사용할 수 있다.

```text
http://localhost:5500/
```

또는

```text
http://127.0.0.1:5500/
```

내가 이해한 방식은 다음과 같다.

```text
localhost = 현재 사용하고 있는 내 컴퓨터
127.0.0.1 = 내 컴퓨터를 의미하는 IP 주소
5500 = Live Server가 사용하고 있는 포트 번호
```

즉,

```text
127.0.0.1:5500
```

은

```text
내 컴퓨터의 5500번 통로에 실행 중인 Web Server
```

라고 이해할 수 있다.

---

# 4. Browser와 Web Server

Browser는 HTML, CSS, JavaScript를 받아서 사용자에게 화면으로 보여주는 프로그램이다.

대표적인 Browser는 다음과 같다.

```text
Chrome
Edge
Safari
Firefox
```

Web Server는 Browser가 요청한 HTML, CSS, JavaScript 파일을 제공한다.

이번 실습에서는 다음 구조로 동작했다.

```text
Browser
   ↓ 요청

Live Server
   ↓ 파일 전달

index.html
   ↓

Browser 화면 출력
```

---

# 5. Live Server

Live Server는 개발할 때 사용할 수 있는 간단한 Web Server이다.

이번 실습에서는 `index.html` 파일을 브라우저에 전달하는 역할을 했다.

```text
VS Code
   ↓

Live Server
   ↓

Browser
```

HTML 파일을 수정한 뒤 저장하면 브라우저에 변경 내용이 빠르게 반영되는 장점이 있다.

---

# 6. Web Server와 API Server의 차이

## Web Server

HTML, CSS, JavaScript 같은 웹 파일을 Browser에 제공한다.

예:

```text
index.html
style.css
script.js
```

이번 실습에서 사용한 Live Server가 여기에 해당한다.

---

## API Server

데이터와 기능을 제공하는 서버이다.

예를 들어 다음과 같은 요청을 처리할 수 있다.

```text
회원 정보 조회
로그인
게시글 저장
상품 조회
주문 처리
```

앞으로 사용할 FastAPI는 API Server 역할을 한다.

정리하면 다음과 같다.

```text
Live Server
→ HTML / CSS / JS 제공

FastAPI
→ 데이터 / 기능 제공
```

# 7. DevTools

Chrome에서 `F12`를 누르면 DevTools를 열 수 있다.

DevTools는 웹페이지가 실제로 어떻게 실행되고 있는지 확인하는 개발 도구이다.

이번 실습에서는 주로 다음 두 기능을 확인했다.

```text
Elements
Network
```

---

# 8. Elements 탭

Elements 탭에서는 브라우저가 실제로 만들어낸 HTML 구조를 확인할 수 있다.

작성한 코드 중 다음 부분을 확인했다.

```html
<h1>Frontend 학습을 시작합니다.</h1>
```

이를 통해 VS Code에서 작성한 HTML 코드가 Browser의 DOM 구조로 만들어졌다는 것을 확인할 수 있다.

흐름은 다음과 같다.

```text
index.html
   ↓

Live Server
   ↓

Browser
   ↓

DOM 생성
   ↓

Elements에서 확인
```

---

# 9. Network 탭

Network 탭에서는 Browser가 Server와 주고받는 요청을 확인할 수 있다.

페이지를 새로고침하면 `index.html` 요청을 확인할 수 있다.

확인할 주요 항목은 다음과 같다.

```text
Request URL
Request Method
Status Code
```

대표적으로 다음과 같이 확인할 수 있다.

```text
Request Method: GET
```

GET은 Browser가 Server에게 데이터를 요청하는 방식 중 하나이다.

이번 실습에서는 Browser가 Live Server에게 다음과 같이 요청한 것이다.

```text
index.html 파일 주세요.
```

Live Server는 요청을 받은 뒤 해당 HTML 파일을 Browser에게 전달한다.

---

# 10. GET 요청 흐름

이번 실습에서 웹페이지가 표시되는 과정은 다음과 같다.

```text
1. Browser에서 주소 입력

2. Browser가 Live Server에 요청

3. GET /index.html

4. Live Server가 index.html 전달

5. Browser가 HTML 해석

6. 화면 출력
```

즉,

```text
Browser
   ↓ GET 요청

Web Server
   ↓ index.html 응답

Browser
   ↓

화면 출력
```

이라는 흐름이다.

# 13. 오늘 발생한 오류

## ERR_CONNECTION_REFUSED

처음 페이지를 실행했을 때 다음 오류가 발생했다.

```text
사이트에 연결할 수 없음

127.0.0.1에서 연결을 거부했습니다.

ERR_CONNECTION_REFUSED
```

원인은 Live Server가 실행되지 않은 상태였기 때문이다.

해결 방법:

```text
index.html 우클릭
→ Open with Live Server
```

실행 후 정상적으로 페이지에 접근할 수 있었다.

이를 통해 주소가 맞더라도 해당 포트에서 서버가 실행되고 있지 않으면 접속할 수 없다는 것을 알게 되었다.

# 14. Browser / Web Server / API Server 정리

```text
Browser
= Frontend가 실행되고 화면이 표시되는 곳

Web Server
= HTML / CSS / JavaScript 파일을 제공하는 서버

API Server
= 데이터와 기능을 제공하는 서버

Live Server
= 현재 실습에서 사용하는 정적 Web Server

FastAPI
= 앞으로 Backend에서 사용할 API Server

localhost
= 내 컴퓨터

127.0.0.1
= 내 컴퓨터를 가리키는 IP 주소

5500
= Live Server가 사용하는 Port

DevTools
= 웹페이지 실행 상태를 확인하는 개발 도구

Git
= 코드 변경 이력을 관리하는 도구

GitHub
= Git으로 관리한 코드를 원격 저장소에 저장하고 공유하는 서비스
```

# 15. 오늘 이해한 핵심 흐름

웹페이지를 실행하면 다음과 같은 흐름으로 동작한다.

```text
VS Code에서 HTML 작성
        ↓
Live Server 실행
        ↓
localhost:5500
        ↓
Browser가 GET 요청
        ↓
Live Server가 index.html 전달
        ↓
Browser가 HTML 해석
        ↓
화면 출력
        ↓
DevTools로 실행 결과 확인
```

그리고 작업이 끝나면

```text
git add
   ↓
git commit
   ↓
git push
   ↓
GitHub
```

순서로 변경 내용을 저장한다.
