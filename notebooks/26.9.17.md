## 1. CSV 파일 경로와 `FileNotFoundError`

CSV 파일을 불러올 때 아래와 같은 오류가 발생했다.

```python
FileNotFoundError: [Errno 2] No such file or directory
```

예를 들어 다음 코드는 현재 Notebook 위치를 기준으로 한 단계 위의 `data/raw` 폴더를 찾는다.

```python
customers = pd.read_csv("../data/raw/customers.csv")
```

Notebook의 위치가 달라지면 상대경로가 맞지 않을 수 있기 때문에 프로젝트 루트를 찾아서 경로를 설정하는 방법을 사용했다.

```python
from pathlib import Path
import pandas as pd

PROJECT_ROOT = Path.cwd().resolve()

while not (PROJECT_ROOT / "data" / "raw").exists():
    if PROJECT_ROOT.parent == PROJECT_ROOT:
        raise FileNotFoundError("data/raw 폴더를 찾을 수 없습니다.")

    PROJECT_ROOT = PROJECT_ROOT.parent

DATA_DIR = PROJECT_ROOT / "data" / "raw"
```

이후 CSV 파일은 다음과 같이 불러올 수 있다.

```python
customers = pd.read_csv(DATA_DIR / "customers.csv")
order_items = pd.read_csv(DATA_DIR / "order_items.csv")
orders = pd.read_csv(DATA_DIR / "orders.csv")
products = pd.read_csv(DATA_DIR / "products.csv")
```

### 배운 점

상대경로는 현재 실행 위치에 따라 달라지므로, 프로젝트 루트를 기준으로 경로를 관리하는 것이 더 안전하다.

## 2. `NameError` 이해하기

그래프를 작성하면서 다음 오류가 발생했다.


```python
x_data = ["korean", "영어", "수학", "과학", "도덕"]
y_data = [75, 70, 87, 88, 59]
```

```python
fig, ax = plt.subplots(figsize=(10, 5))

plt.show()
```

### 배운 점

`NameError`가 발생하면 가장 먼저 해당 변수가 이전에 정의되었는지 확인해야 한다.

## 3. Python 모듈 import 오류

다음 코드를 실행했을 때 오류가 발생했다.

```python
from src.visualization import setup_korean_font
```

오류:

```python
ModuleNotFoundError: No module named 'src.visualization'
```

`src` 폴더를 확인해보니 다음과 같은 파일이 있었다.

```text
src/
├── app.py
├── midterm_project.py
├── preprocessing.py

```

`visualization.py` 파일은 존재하지 않았다.

```text

```

따라서 import 경로를 수정했다.

```python

setup_korean_font()
```

### 배운 점

Python의 import 경로는 실제 폴더와 파일 구조를 따라야 한다.

```python

```

예를 들어

```text
src/midterm_project.py
```

안에 함수가 있다면

```python
from src.midterm_project import setup_korean_font
```

으로 불러온다.

## 8. `groupby()`와 `agg()`

데이터를 특정 기준으로 묶고 집계하기 위해 `groupby()`와 `agg()`를 사용했다.

예를 들어 고객별 구매금액과 주문 횟수를 계산할 수 있다.

```python
customer_sales = (
    df_visualization
    .groupby(
        "customer_id",
        dropna=False,
        as_index=False
    )
    .agg(
        total_amount=("line_total", "sum"),
        order_count=("order_id", "nunique")
    )
    .sort_values(
        "total_amount",
        ascending=False
    )
)
```

결과 확인:

```python
customer_sales.head()
```

### 코드 의미

```python
groupby("customer_id")
```

고객별로 데이터를 묶는다.

```python
total_amount=("line_total", "sum")
```

고객별 전체 구매금액을 계산한다.

```python
order_count=("order_id", "nunique")
```

고객별 서로 다른 주문번호 개수를 계산한다.

```python
ascending=False
```

구매금액이 큰 고객부터 내림차순으로 정렬한다.

## 9. `nunique()`

`nunique()`는 중복을 제거한 고유한 값의 개수를 계산한다.

예를 들어 한 고객이 하나의 주문에서 여러 상품을 구매했다면 `order_id`가 여러 행에 반복될 수 있다.

따라서 단순히 행 개수를 세는 것보다 다음 방법이 정확하다.

```python
order_count=("order_id", "nunique")
```

즉,

```text
고객별 서로 다른 주문번호 개수
```

를 주문 횟수로 계산한다.

## 11. 문자열과 숫자 타입이 섞였을 때 발생하는 오류

막대그래프를 만들면서 다음 오류가 발생했다.

```text
TypeError:
'value' must be an instance of str or bytes,
not a float
```

카테고리처럼 문자열이어야 할 데이터에 숫자 또는 다른 타입이 섞여 있으면 Matplotlib에서 문제가 발생할 수 있다.

데이터 타입 확인:

```python
category_sales.dtypes
```

고유값 확인:

```python
category_sales["category"].unique()
```

각 값의 타입 확인:

```python
for value in category_sales["category"]:
    print(value, type(value))
```

필요한 경우 문자열 타입으로 변환할 수 있다.

```python
category_sales["category"] = (
    category_sales["category"].astype(str)
)
```

### 배운 점

오류가 발생했을 때 단순히 결측치만 확인하지 말고 컬럼의 데이터 타입도 함께 확인해야 한다.

## 12. 전처리한 DataFrame과 기존 DataFrame의 차이

다음과 같이 `df_visualization`에서 결측치를 제거했더라도

```python
df_visualization = df_visualization.dropna()
```

이미 그 전에 만들어둔 `category_sales`가 자동으로 변경되는 것은 아니다.

예를 들어

```python
category_sales = df_visualization.groupby(...)
```

를 실행한 뒤 `df_visualization`을 수정했다면, `category_sales`는 이전 상태를 그대로 유지한다.

따라서 원본 DataFrame을 수정했다면 필요한 집계 DataFrame도 다시 만들어야 한다.

### 배운 점

Pandas에서 새로운 DataFrame을 만들어 놓으면 원본 DataFrame을 수정한다고 자동으로 결과가 갱신되는 것은 아니다.

## 13. 산점도(Scatter Plot)

오늘 상품 가격과 판매 수량의 관계를 산점도로 확인했다.

산점도에서는:

```text
X축 = 상품 가격
Y축 = completed 판매 수량
점 하나 = 하나의 상품
```

그래프에서 대부분의 상품은 낮은 가격 구간에 집중되어 있었고 판매 수량도 비슷한 영역에 모여 있었다.

일부 상품은 가격과 판매 수량이 다른 상품들보다 매우 높은 값을 가지고 있었다.

이러한 값은 이상치 후보가 될 수 있다.

### 해석

전체적으로 가격이 높아질수록 판매량도 일부 증가하는 모습이 보였지만, 점들이 넓게 분포하기 때문에 가격이 높을수록 반드시 판매량이 높다고 단정할 수는 없다.

또한 일부 큰 값이 전체 관계에 영향을 줄 수 있기 때문에 이상치 여부를 확인해야 한다.

## 오늘의 핵심 정리

오늘 수업을 통해 단순히 코드를 실행하는 것보다 데이터와 프로젝트 구조를 확인하는 것이 중요하다는 것을 배웠다.

특히 다음 내용을 기억해야겠다.

1. CSV 경로는 현재 Notebook 실행 위치를 기준으로 확인한다.
2. CSV 파일은 `pd.read_csv()`로 불러와야 DataFrame으로 사용할 수 있다.
3. `NameError`가 발생하면 변수가 먼저 만들어졌는지 확인한다.
4. Python import는 실제 폴더 및 파일 구조와 일치해야 한다.
5. 날짜 데이터는 `pd.to_datetime()`을 이용해 날짜 타입으로 변환할 수 있다.
6. `dropna()`는 결측치를 제거하지만 잘못된 데이터 타입까지 해결해주는 것은 아니다.
7. `groupby()`와 `agg()`를 이용하면 그룹별 합계와 개수를 계산할 수 있다.
8. `nunique()`를 사용하면 중복을 제외한 고유값 개수를 계산할 수 있다.
9. 원본 DataFrame을 수정해도 이전에 만든 집계 DataFrame은 자동으로 갱신되지 않는다.
10. 산점도는 두 숫자형 변수 사이의 관계를 확인하는 데 유용하다.
11. 그래프를 해석할 때 이상치가 전체 관계에 미치는 영향도 확인해야 한다.

오늘은 Pandas의 데이터 처리 과정과 Matplotlib 시각화를 직접 연결해보면서, 데이터 분석에서는 전처리 → 집계 → 시각화 → 해석의 흐름이 중요하다는 것을 배웠다.
