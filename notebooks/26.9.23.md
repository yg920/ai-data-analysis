잘못된 구조:

```text
신규 발견
↓
history 저장
↓
API 실패
```

그러면 실제 전달되지 않은 공고가 처리 완료된 것으로 기록된다.

개선:

```text
신규 발견
↓
분석
↓
AI
↓
Report
↓
Slack
↓
Gmail
↓
모두 성공
↓
history 저장
```

---

# 101. 외부 API 실패를 숨기면 안 되는 이유

예:

```text
Gemini 503
```

인데 프로그램이:

```text
완료
```

라고 출력하면 사용자는 시스템이 정상 동작했다고 오해할 수 있다.

따라서:

```text
실패
→ 명확한 예외
→ non-zero exit
```

가 중요하다.

---

# 102. API 호출 수를 줄이는 이유

현재 검색어 `AI`로 잡코리아를 검색해도 모든 결과가 실제 AI 직무는 아니다.

따라서:

```text
신규 공고
↓
키워드 관련성 필터
↓
관련 공고
↓
Gemini
```

순으로 처리하면:

```text
비용 감소
속도 개선
503 위험 감소
불필요한 분석 감소
```

효과가 있다.

# 103. 오늘 발견한 실제 데이터 문제

검색어:

```text
AI
```

라고 검색했다고 해서 모든 결과가 AI 공고인 것은 아니다.

예:

```text
보험설계사
영상편집자
```

같은 공고도 검색 결과에 나올 수 있다.

따라서 검색 결과 자체를 그대로 AI 공고라고 보면 안 된다.


# 106. 코드에 인증정보를 넣지 않는 이유

```python
os.getenv(...)
```

를 사용한다.

# 117. 오늘 가장 중요하게 배운 점

## 1. 검색 결과와 실제 관련 공고는 다르다

```text
AI 검색
≠
모든 공고가 AI 직무
```

따라서 필터링이 필요하다.

---

## 2. 계산은 pandas가 한다

```text
건수
통계
분포
```

등 객관적 수치는 pandas가 담당한다.

---

## 3. Gemini는 설명을 담당한다

```text
요약
직무 유형
AX 관련성
추천 이유
```

를 담당한다.

---

## 4. AI 출력은 검증해야 한다

```text
AI 생성
≠
사실
```

따라서 Human Verification이 필요하다.

---

## 5. 실패 처리도 기능이다

Gemini가 실패했을 때:

```text
History가 보호되고
후속 알림이 가지 않고
완료 메시지가 나오지 않는 것
```

도 중요한 정상 동작이다.

---

## 6. 상태 저장 시점이 중요하다

```text
작업 시작
```

했다고 history에 기록하는 것이 아니라:

```text
실제 작업이 성공
```

한 뒤 기록해야 한다.

---

## 7. Notebook과 운영 코드는 역할이 다르다

```text
Notebook
→ 검증

src/
→ 기능

main.py
→ 실행 순서
```

---

## 8. 자동화 전에 로컬 검증이 필요하다

```text
Local Success
↓
GitHub Actions
```

순서가 중요하다.
