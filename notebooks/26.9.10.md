## 1. 데이터 전처리란?

데이터 전처리는 분석하기 전에 데이터를 정리하고 분석 가능한 상태로 만드는 과정이다.

전처리의 목적은 데이터를 무조건 많이 수정하는 것이 아니라 다음을 확인하는 데 있다.

- 왜 데이터를 바꿨는가
- 무엇이 달라졌는가
- 처리 결과를 다시 재현할 수 있는가

전체 흐름은 다음과 같다.

```text
원본 확인
→ 전처리 전 상태 기록
→ 문자열 정리
→ 숫자·날짜 변환
→ 변환 실패 확인
→ 결측 처리 기준 결정
→ 전체 중복·키 중복 구분
→ 범주값 표준화
→ 이상값 후보 검토
→ 파생 컬럼 생성
→ PK/FK 관계 재검증
→ processed CSV 저장
→ 반복 실행
→ 저장 결과 재검증
→ 전처리 보고서 확인
→ LLM 제안 검증
→ Evidence + 해석 작성
→ GitHub 업로드
→ LMS 제출
```

## 2. pandas와 전처리의 관계

전처리는 해야 하는 작업이고, pandas는 그 작업을 수행하는 Python 라이브러리이다.

```text
전처리 = 데이터 정리 작업
pandas = 그 작업을 수행하는 도구
```

예를 들어 결측치를 확인하는 것은 전처리 작업이고,

```python
df.isna().sum()
```

은 그 작업을 수행하는 pandas 코드이다.

## 15. 전체 행 중복과 키 중복의 차이

완전히 같은 행이 반복되는 것과 ID가 중복되는 것은 다른 문제이다.

```text
전체 행 중복
≠
PK 중복
≠
FK 반복
```

예를 들어:

```text
order_items.order_id
```

는 같은 주문에 여러 상품이 포함될 수 있기 때문에 반복될 수 있다.

즉, FK 반복을 무조건 중복 오류라고 보면 안 된다.

## 17. 이상값 확인

이상값은 일반적인 범위를 벗어난 값이다.

### 나이 확인

```python
customers_clean.loc[
    (customers_clean["age"] < 0)
    | (customers_clean["age"] > 120)
]
```

### 상품 가격 확인

```python
products_clean.loc[
    products_clean["price"] <= 0
]
```

### 주문 수량 확인

```python
order_items_clean.loc[
    order_items_clean["quantity"] <= 0
]
```

### 판매 단가 확인

```python
order_items_clean.loc[
    order_items_clean["unit_price"] <= 0
]
```

중요한 점:

```text
이상값 후보 = 무조건 삭제 대상
```

은 아니다.

예를 들어:

```text
0원 상품 → 증정품 가능
음수 수량 → 반품 가능
0원 단가 → 프로모션 가능
```

따라서 업무적인 의미를 확인한 뒤 처리해야 한다.

## 23. merge란?

merge는 서로 다른 DataFrame을 공통된 key를 기준으로 연결하는 기능이다.

예:

```text
order_items
+
orders
```

공통 컬럼:

```text
order_id
```

코드:

```python
order_sales = order_items.merge(
    orders,
    on="order_id",
    how="left"
)
```

쉽게 말하면:

```text
서로 다른 표를 공통 번호를 기준으로 붙이는 작업
```

이다.

---

## 24. merge의 key

key는 두 DataFrame을 연결하는 기준값이다.

현재 데이터에서는 다음처럼 연결할 수 있다.

```text
order_items ↔ orders
order_id

order_items ↔ products
product_id

orders ↔ customers
customer_id
```

---

## 25. left merge

```python
how="left"
```

의 의미는 왼쪽 DataFrame의 모든 행을 유지하는 것이다.

```python
order_sales = order_items.merge(
    orders,
    on="order_id",
    how="left"
)
```

의미:

```text
order_items의 모든 행은 유지하고
orders에서 일치하는 정보를 붙인다.
```

---

## 26. inner merge

```python
how="inner"
```

은 양쪽 DataFrame에 모두 존재하는 데이터만 남긴다.

```text
left
→ 왼쪽 데이터 유지

inner
→ 양쪽에 모두 존재하는 데이터만 유지
```

---

## 27. many_to_one

merge 관계를 검증하기 위해 사용할 수 있다.

```python
validate="many_to_one"
```

예:

```text
order_items

order_id
1
1
1
2
2
```

한 주문에 상품이 여러 개 있을 수 있기 때문에 같은 `order_id`가 반복될 수 있다.

반면 `orders`에서는:

```text
order_id
1
2
```

처럼 주문 하나당 한 행이어야 한다.

따라서:

```text
order_items = many
orders = one
```

관계이다.

## 28. indicator

merge 결과가 정상적으로 연결됐는지 확인할 때 사용한다.

```python
df.merge(
    orders,
    on="order_id",
    how="left",
    indicator=True
)
```

그러면 `_merge` 컬럼이 생성된다.

```text
both
left_only
right_only
```

의미:

```text
both
→ 양쪽 데이터에 모두 존재

left_only
→ 왼쪽 데이터에만 존재

right_only
→ 오른쪽 데이터에만 존재
```

확인:

```python
df["_merge"].value_counts()
```

## 29. merge가 잘못되면 생기는 문제

merge key가 잘못되거나 중복되어 있으면 행 수가 예상보다 증가할 수 있다.

예:

```text
원래 데이터: 2행
merge 결과: 4행
```

이 상태에서 매출을 계산하면 실제보다 크게 계산될 수 있다.

따라서 merge 후에는 반드시 확인해야 한다.

```python
len(df)
df["_merge"].value_counts()
```

그리고 관계도 검증한다.

```python
validate="many_to_one"
```

---

## pandas

pandas는 CSV를 읽고 데이터를 정리하고 분석할 수 있도록 도와주는 Python 라이브러리이다.

```text
전처리 = 작업
pandas = 작업을 수행하는 도구
```

---

## merge

merge는 서로 다른 DataFrame을 공통 key를 기준으로 연결하는 기능이다.

```text
order_items + orders
→ order_id

order_items + products
→ product_id

orders + customers
→ customer_id
```

---

## many_to_one

```text
many
→ 같은 key가 여러 번 나올 수 있음

one
→ 같은 key가 한 번만 나와야 함
```

예:

```text
order_items.order_id
→ 여러 번 가능

orders.order_id
→ 한 번만 존재해야 함
```

그래서:

```python
validate="many_to_one"
```

으로 관계를 검증할 수 있다.
