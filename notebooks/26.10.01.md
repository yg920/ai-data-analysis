# TIL - Python 모듈 오류 해결과 데이터 구조·민감정보 점검

## 오늘 학습한 내용

오늘은 Python 프로젝트에서 발생한 `ModuleNotFoundError`, `ImportError`, `FileNotFoundError`를 순서대로 해결하면서 프로젝트 구조와 모듈 경로에 대해 학습했다.

또한 공통 함수를 사용하지 않고 직접 CSV 파일을 읽어 데이터셋 구조와 컬럼 정보를 요약하고, 민감정보 가능성을 검토하는 코드를 작성했다.

---

# 1. Python 모듈 import 오류 해결

처음 실행한 명령어는 다음과 같았다.

```powershell
python scripts/preprocess_data.py
```

실행 과정에서 다음 오류가 발생했다.

```text
ModuleNotFoundError: No module named 'src'
```

이 오류는 Python이 프로젝트의 `src` 폴더를 모듈 경로로 인식하지 못했기 때문에 발생했다.

이를 해결하기 위해 프로젝트 루트 경로를 Python 모듈 검색 경로에 추가했다.

```python
from pathlib import Path
import sys

PROJECT_ROOT = Path(__file__).resolve().parent.parent
sys.path.insert(0, str(PROJECT_ROOT))
```

### 배운 점

Python에서 다른 폴더의 모듈을 import하려면 해당 경로가 Python의 모듈 검색 경로에 포함되어 있어야 한다.

# 2. ImportError 원인 확인

이후 다음 코드를 사용했다.

```python
from src.preprocessing import load_sales_data
```

하지만 다음 오류가 발생했다.

```text
ImportError: cannot import name 'load_sales_data'
```

`src/preprocessing.py` 파일 자체는 존재하지만 그 안에 `load_sales_data` 함수가 없었기 때문에 발생한 오류였다.

함수 위치를 찾기 위해 다음 PowerShell 명령어를 사용했다.

```powershell
Get-ChildItem -Recurse -Filter *.py | Select-String "load_sales_data"
```

검색 결과 `load_sales_data` 함수는 사용되고 있었지만 실제 함수 정의는 존재하지 않았다.

따라서 `src/data_loader.py` 파일이 필요하다는 것을 확인했다.

# 3. data_loader.py 생성

`src` 폴더 안에 새로운 파일을 만들었다.

```text
src/
├─ __init__.py
├─ app.py
├─ midterm_project.py
├─ preprocessing.py
└─ data_loader.py
```

`data_loader.py`에서는 CSV 데이터를 불러오는 기능을 구현했다.

예시 구조는 다음과 같다.

```python
from pathlib import Path
import pandas as pd


def load_csv(path):
    path = Path(path)

    if not path.exists():
        raise FileNotFoundError(
            f"파일을 찾을 수 없습니다: {path}"
        )

    return pd.read_csv(path)


def load_sales_data(base_dir):
    base_dir = Path(base_dir)

    return {
        "customers": load_csv(base_dir / "customers.csv"),
        "products": load_csv(base_dir / "products.csv"),
        "orders": load_csv(base_dir / "orders.csv"),
        "order_items": load_csv(base_dir / "order_items.csv"),
    }
```

### 배운 점

하나의 함수가 여러 곳에서 사용된다면 별도의 Python 파일로 분리하면 재사용하기 쉽다.

예를 들어:

```text
data_loader.py
```

는 데이터 불러오기 역할을 담당하고,

```text
preprocessing.py
```

는 데이터 전처리 역할을 담당하도록 나눌 수 있다.

# 4. FileNotFoundError 해결

모듈 문제를 해결한 뒤 다음 오류가 발생했다.

```text
FileNotFoundError:
파일을 찾을 수 없습니다:
practice\chapter05\data\raw\customers.csv
```

이번 오류는 코드 자체의 문제가 아니라 CSV 파일 경로가 잘못 설정되어 있었기 때문이다.

프로그램은 다음 위치에서 파일을 찾고 있었다.

```text
practice/chapter05/data/raw/
```

하지만 실제 데이터는 프로젝트의 다음 위치에 있었다.

```text
data/raw/
```

따라서 경로를 프로젝트 루트 기준으로 수정했다.

```python
RAW_DIR = PROJECT_ROOT / "data" / "raw"
PROCESSED_DIR = PROJECT_ROOT / "data" / "processed"
```

### 배운 점

`FileNotFoundError`가 발생하면 가장 먼저 실제 파일 위치와 코드에 작성된 경로가 같은지 확인해야 한다.

# 5. Python 오류를 해석하는 순서

오늘 발생한 오류를 순서대로 정리하면 다음과 같다.

```text
ModuleNotFoundError
↓
Python이 모듈 또는 폴더를 찾지 못함

ImportError
↓
모듈 파일은 찾았지만 필요한 함수가 없음

FileNotFoundError
↓
코드는 실행되지만 필요한 데이터 파일을 찾지 못함
```

오류 메시지의 가장 마지막 부분을 확인하면 문제 원인을 빠르게 찾을 수 있다.

# 6. 원본 행 없이 데이터 구조 점검

다음 실습에서는 실제 데이터 행이나 실제 값을 보여주지 않고 데이터 구조만 분석했다.

분석 대상 폴더는 다음과 같다.

```text
data/processed
```

먼저 CSV 파일 목록을 확인했다.

```python
from pathlib import Path
import pandas as pd

processed_dir = Path("data/processed")

csv_files = list(processed_dir.glob("*.csv"))

for file in csv_files:
    print(file.name)
```

---

# 7. 데이터셋 구조 요약

각 CSV 파일의 행 수와 컬럼 수를 확인했다.

```python
dataset_summary_list = []

for file_path in csv_files:

    df = pd.read_csv(file_path)

    dataset_summary_list.append({
        "dataset_name": file_path.stem,
        "row_count": len(df),
        "column_count": len(df.columns),
    })

dataset_summary = pd.DataFrame(dataset_summary_list)

display(dataset_summary)
```

### 확인할 수 있는 정보

```text
dataset_name
row_count
column_count
```

이를 통해 실제 데이터 값을 공개하지 않고도 데이터셋의 전체 크기를 확인할 수 있다.

---

# 8. 컬럼 구조 요약

각 컬럼의 자료형, 결측치 수, 고유값 개수를 확인했다.

```python
column_summary_list = []

for file_path in csv_files:

    df = pd.read_csv(file_path)

    for column in df.columns:

        column_summary_list.append({
            "dataset_name": file_path.stem,
            "column_name": column,
            "dtype": str(df[column].dtype),
            "missing_count": df[column].isna().sum(),
            "unique_count": df[column].nunique(dropna=True),
        })

column_summary = pd.DataFrame(column_summary_list)

display(column_summary)
```

### 주요 확인 항목

```text
column_name
dtype
missing_count
unique_count
```

# 9. 민감정보 가능성 검토

컬럼명을 기준으로 개인정보 또는 민감정보 가능성을 확인했다.

식별 가능성이 있는 대표적인 키워드는 다음과 같다.

```python
identifier_keywords = [
    "id",
    "name",
    "email",
    "phone",
    "address",
    "customer",
    "user",
    "member"
]
```

민감정보 가능성이 있는 키워드는 다음과 같다.

```python
sensitive_keywords = [
    "gender",
    "sex",
    "age",
    "birth",
    "salary",
    "income",
    "health",
    "religion",
    "race"
]
```

# 10. 민감정보 검토 결과 항목

민감정보 검토 결과에는 다음 항목을 포함했다.

```text
sensitivity_reason
column_name_share_policy
share_raw_values
low_cardinality_review
```

각 항목의 의미는 다음과 같다.

## sensitivity_reason

해당 컬럼이 민감하거나 식별 가능성이 있는 이유를 기록한다.

예:

```text
개인을 식별할 가능성이 있는 컬럼
민감정보 또는 개인정보 가능성이 있는 컬럼
```

---

## column_name_share_policy

컬럼명 자체를 외부에 공유해도 되는지 검토한다.

예:

```text
yes
review
```

---

## share_raw_values

실제 데이터 값을 외부에 공유할 것인지 나타낸다.

이번 실습에서는 모든 컬럼에 대해 다음 값을 사용했다.

```text
no
```

즉 실제 이름, ID, 이메일 등의 값을 Context에 포함하지 않는다.

---

## low_cardinality_review

고유값 개수가 적은 컬럼을 별도로 확인한다.

예를 들어 다음과 같은 데이터는 범주의 수가 적을 수 있다.

```text
gender
region
membership_grade
status
```

고유값 수가 너무 적으면 다른 정보와 결합했을 때 특정 개인을 추정할 위험이 생길 수 있다.

따라서 소수 범주에 대해서도 별도의 검토가 필요하다.

# 11. 원본 데이터 값을 출력하지 않은 이유

이번 실습에서는 다음 코드 사용을 최소화했다.

```python
df.head()
df.sample()
df["column"].unique()
```

이러한 코드는 실제 데이터 값을 화면에 보여줄 수 있기 때문이다.

대신 다음과 같은 구조 정보만 사용했다.

```python
len(df)

df.columns

df.dtypes

df.isna().sum()

df.nunique()
```

이를 통해 실제 데이터를 공개하지 않고 데이터 구조를 파악할 수 있다.

# 12. 오늘 실습의 성공 기준

다음 조건을 만족하면 구조 요약과 민감정보 검토가 정상적으로 수행된 것이다.

```text
1. 실제 행을 Context에 넣지 않는다.

2. 실제 데이터 값 예시를 사용하지 않는다.

3. share_raw_values 값은 no로 설정한다.

4. ID, 이름 등 식별자 값을 공유하지 않는다.

5. 민감할 가능성이 있는 컬럼명도 별도로 검토한다.

6. 고유값 수가 적은 컬럼의 재식별 위험을 검토한다.
```

# 13. 오늘 배운 핵심 정리

오늘 가장 중요하게 배운 내용은 다음과 같다.

```text
ModuleNotFoundError
→ Python이 파일 또는 모듈을 찾지 못한 문제

ImportError
→ 파일은 찾았지만 필요한 함수가 없는 문제

FileNotFoundError
→ 데이터 파일 경로가 잘못된 문제
```

그리고 데이터 분석에서는 단순히 데이터를 불러오는 것뿐 아니라 데이터 공유 전에 개인정보와 민감정보를 검토하는 과정도 중요하다는 것을 배웠다.

특히 LLM이나 외부 서비스에 데이터를 전달할 때는 실제 행을 그대로 전달하기보다 다음과 같은 구조 정보만 사용하는 것이 안전하다.

```text
행 수
컬럼 수
컬럼명
자료형
결측치 수
고유값 수
민감정보 여부
```
