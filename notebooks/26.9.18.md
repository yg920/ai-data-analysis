# 1. PostgreSQL 실습 환경 확인

데이터베이스 작업을 시작하기 전에 현재 어떤 데이터베이스와 사용자로 접속되어 있는지 확인했다.

```sql
SELECT current_database();
SELECT current_user;
SELECT current_schema();

SHOW search_path;
```

### 각각의 의미

* `current_database()` : 현재 접속 중인 데이터베이스 이름
* `current_user` : 현재 PostgreSQL에 접속한 사용자
* `current_schema()` : 현재 기본으로 사용 중인 스키마
* `SHOW search_path` : 테이블을 조회할 때 PostgreSQL이 스키마를 찾는 순서

예를 들어 `search_path`가 다음과 같다면

```text
"$user", public
```

현재 사용자 이름과 같은 스키마를 먼저 찾고, 없으면 `public` 스키마를 찾는다.

# 2. transaction_read_only 확인

현재 데이터베이스 연결이 읽기 전용인지 확인할 수 있다.

```sql
SHOW transaction_read_only;
```

결과가

```text
off
```

라면 데이터를 생성하거나 수정할 수 있는 상태이다.

반대로

```text
on
```

이라면 읽기 전용 상태이므로 `CREATE`, `INSERT`, `UPDATE`, `DELETE` 등의 작업이 제한될 수 있다.

---

# 3. 트랜잭션

여러 SQL 작업을 하나의 작업 단위로 처리할 때 트랜잭션을 사용할 수 있다.

```sql
BEGIN;

-- 여러 SQL 작업

COMMIT;
```

문제가 발생했을 경우에는

```sql
ROLLBACK;
```

을 사용해서 작업 이전 상태로 되돌릴 수 있다.

### 트랜잭션을 사용하는 이유

여러 테이블이나 데이터를 한꺼번에 생성하는 과정에서 일부 작업만 성공하는 상황을 방지할 수 있다.

즉,

```text
모두 성공 → COMMIT
문제 발생 → ROLLBACK
```

방식으로 데이터의 일관성을 지킬 수 있다.

# 4. PostgreSQL DO 블록

PostgreSQL에서는 `DO` 블록을 사용해 조건문이나 예외 처리를 포함한 SQL을 작성할 수 있다.

```sql
DO $$
BEGIN

    IF current_database() <> 'ai_database_book' THEN
        RAISE EXCEPTION
            '현재 데이터베이스를 확인하세요.';
    END IF;

END $$;
```

단순 SQL 실행뿐만 아니라 실행 환경이 올바른지도 검사할 수 있다는 점이 중요하다.

현재 사용자가 데이터베이스에 특정 권한을 가지고 있는지 확인할 수 있다.

# 6. 스키마를 사용하는 이유

스키마는 데이터베이스 안에서 테이블들을 논리적으로 구분하는 공간이다.

구조를 간단하게 표현하면 다음과 같다.

```text
PostgreSQL 서버
    ↓
Database
    ↓
Schema
    ↓
Table
    ↓
Row / Column
```

예를 들어

```sql
course_project.students
```

에서

```text
course_project = 스키마
students       = 테이블
```

이다.

프로젝트별로 스키마를 나누면 테이블을 관리하기 편해진다.

---

# 7. JOIN 복습

JOIN은 서로 다른 테이블에 나누어 저장된 데이터를 하나의 결과로 연결해서 조회하는 기능이다.

예를 들어

```text
students
courses
enrollments
```

와 같이 학생, 강의, 수강신청 데이터가 각각 다른 테이블에 저장되어 있을 수 있다.

이때 JOIN을 이용하면

```text
학생 이름 + 신청 강의 + 신청 날짜
```

와 같은 정보를 한 번에 조회할 수 있다.

---

# 8. INNER JOIN

양쪽 테이블에 모두 존재하는 데이터만 조회한다.

```sql
SELECT
    s.name,
    e.course_id
FROM students s
INNER JOIN enrollments e
    ON s.student_id = e.student_id;
```

### 특징

```text
students에만 존재하는 학생 → 제외
enrollments에만 존재하는 데이터 → 제외
양쪽 모두 연결되는 데이터 → 조회
```

---

# 9. LEFT JOIN

왼쪽 테이블의 데이터는 모두 유지하면서 오른쪽 테이블의 데이터를 연결한다.

```sql
SELECT
    s.name,
    e.course_id
FROM students s
LEFT JOIN enrollments e
    ON s.student_id = e.student_id;
```

수강신청을 하지 않은 학생도 조회하고 싶을 때 사용할 수 있다.

수강신청 정보가 없다면 오른쪽 테이블의 값은 `NULL`이 된다.

---

# 10. JOIN에서 ON의 의미

JOIN에서는 어떤 컬럼을 기준으로 두 테이블을 연결할지 지정해야 한다.

```sql
ON s.student_id = e.student_id
```

의 의미는

```text
students.student_id
        =
enrollments.student_id
```

가 같은 행끼리 연결하겠다는 뜻이다.

---

# 11. 테이블 별칭 Alias

JOIN을 사용할 때 테이블 이름이 길어지기 때문에 별칭을 자주 사용한다.

```sql
FROM students s
JOIN enrollments e
```

이후에는

```sql
s.student_id
e.student_id
```

처럼 짧게 사용할 수 있다.

# 12. Python 텍스트 분석

Python에서는 문장을 단어 단위로 분리하고 각 단어가 몇 번 등장했는지 계산할 수 있다.

대표적으로 `Counter`를 사용할 수 있다.

```python
from collections import Counter

counter = Counter(words)
```

예를 들어

```python
words = [
    "AI",
    "데이터",
    "AI",
    "Python",
    "AI",
]
```

라면 결과는 다음과 비슷하다.

```python
Counter({
    "AI": 3,
    "데이터": 1,
    "Python": 1
})
```

---

# 13. Counter

`Counter`는 각 값이 몇 번 등장했는지 자동으로 계산해주는 자료구조이다.

```python
from collections import Counter

final_counter = Counter(words)
```

Dictionary와 비슷한 구조를 가진다.

```text
단어 → 등장 횟수
```

형태이기 때문에 Word Cloud에서도 바로 사용할 수 있다.

# 15. 한글 Word Cloud와 폰트

Word Cloud에서 한글을 정상적으로 표시하려면 한글을 지원하는 폰트 파일을 지정해야 한다.

# 16. Word Cloud 생성

단어 빈도를 이용해 Word Cloud를 생성할 수 있다.

```python
from wordcloud import WordCloud

wordcloud = WordCloud(
    font_path=str(FONT_PATH),
    width=1200,
    height=700,
    background_color="white",
    max_words=100,
    random_state=42,
).generate_from_frequencies(final_counter)
```

### 주요 옵션

| 옵션                 | 의미                   |
| ------------------ | -------------------- |
| `font_path`        | 사용할 폰트 위치            |
| `width`            | 이미지 너비               |
| `height`           | 이미지 높이               |
| `background_color` | 배경색                  |
| `max_words`        | 표시할 최대 단어 수          |
| `random_state`     | 실행할 때 단어 배치를 동일하게 유지 |

---

# 17. generate_from_frequencies()

단어와 빈도수가 저장된 데이터를 이용해 Word Cloud를 생성한다.

```python
.generate_from_frequencies(final_counter)
```

`final_counter`가 다음과 같다면

```python
{
    "AI": 15,
    "데이터": 10,
    "Python": 7
}
```

`AI`가 가장 크게 표시되고 `Python`은 상대적으로 작게 표시된다.

즉,

```text
빈도 높음 → 글자 크게
빈도 낮음 → 글자 작게
```

표현된다.

# 오늘 중요하게 기억할 것

### 1. JOIN은 나누어 저장된 데이터를 연결하는 기능이다.

```text
PK ↔ FK
```

관계를 기준으로 여러 테이블을 연결한다.

### 2. INNER JOIN과 LEFT JOIN의 차이를 기억한다.

```text
INNER JOIN
→ 양쪽에 모두 존재하는 데이터

LEFT JOIN
→ 왼쪽 데이터는 모두 유지
```

### 3. SQL 실행 전 환경 확인이 중요하다.

```sql
SELECT current_database();
SELECT current_user;
SELECT current_schema();

SHOW search_path;
SHOW transaction_read_only;
```

잘못된 데이터베이스에서 SQL을 실행하는 실수를 예방할 수 있다.

### 4. Counter는 단어 빈도 분석에 매우 유용하다.

```python
Counter(words)
```

만으로 단어 등장 횟수를 쉽게 계산할 수 있다.

### 5. 한글 Word Cloud에서는 폰트 설정이 중요하다.

```python
font_path=str(FONT_PATH)
```

한글 폰트가 지정되지 않으면 한글이 정상적으로 표시되지 않을 수 있다.

### 6. Word Cloud는 빈도를 시각적으로 표현한다.

```text
많이 나온 단어 → 크게
적게 나온 단어 → 작게
```

그래서 전체 텍스트에서 어떤 키워드가 많이 등장했는지 빠르게 확인할 수 있다.
